## 共同架构原则

- **本地优先**：1.0.0 没有云端账号或同步；2.0.0 才规划独立设备同步。
- **一个写入者**：Desktop Core 保存桌面资料；连接插件只读取词卡和提交采集，桌面学习状态由 Core 计算。
- **资料归属明确**：连接时封存独立资料 A，使用桌面资料 B+C；明确断开后恢复 A，临时失联时不能静默写回 A。
- **证据与交付分开**：分别记录源码单元测试、真实客户端测试、实际包测试和各平台人工验收；工作流配置不能证明产品已发布或已在线上验证。
- **公共资源只读**：词包安装不重建个人学习库；身份、规则与版本不能仅靠词头猜测。

设计解释放在[官方文档源码](https://github.com/leximeet/leximeet.github.io/tree/main/docs/设计文档)，完整实现与正式接口留在所属仓库。组织首页提供阅读入口，不另存一份容易与原仓库不一致的全量 API、表结构或测试计数。

## 维护这个仓库

修改首页时同时核对真实项目 README 和当前路线，检查 Markdown 相对链接与远端仓库目标。不得加入尚未发布的下载 / 商店 / 云服务承诺、虚构维护者或联系邮箱，不上传私有资料和过程日志。完成后更新 CHANGELOG 与中文提交说明；推送和发布由维护者明确授权。

本仓随正式 `1.0.0` 软件版本更新文档，不单独打产品版本标签。首次公开整理保留远端原始 `init commit`，将后续开发历史压缩为一个当前结果提交；完整开发历史在私有备份中保留，不随公开 main 推送。提交前运行 `npm ci --ignore-scripts && npm run verify`；main、PR 与手动工作流检查链接、图表原字节和格式。步骤与后续版本原则见[维护与发布](docs/维护与发布.md)。
